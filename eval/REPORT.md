# 评测报告（一页）

> 数据来源 `eval/baseline.json`（配置指纹 `c573b7`，`retrieval_mode=vector`，`top_k=6`）。
> 所有数字都能用文末一条命令复现；改代码后先跑 `scripts/diff_eval.py --fail-on-regression`。

## 结论

14 篇消防规范、1335 个切片、本地 bge-m3（1024 维）、纯向量检索：
**严格口径 `hit@6` 82.5% / 宽松口径 87.5%，MRR 0.589 / 0.622，拒答题零幻觉（0/10）。**
40 道有答案题里，端到端答对 32 道（80%）；没答对的 8 道里，5 道是检索没排进 top-6，
3 道是排进去了但模型拒答——**两类问题要分开修，混在一起统计只会得出错误结论**。

## 方法

- **两条通道**：`/search` 不过阈值、不调模型，用来测召回；`/query` 才测拒答与生成。
  用 `/query` 的 citations 算召回，会把「分数低被阈值拦掉」误记成「没检索到」。
- **gold 标锚点不标 chunk_id**：锚点记 `(文件, 页码, 原文)`，启动时三级降级反查
  （同页 → 同文件 → 全库）。切片口径一改，chunk_id 全废，锚点还能用。
- **一个锚点收多个切片**：`chunk_overlap=150` 会让同一句落在相邻两片，跨页段落也会重复。
  只认第一片会把切片重叠算成检索失败——这一条 bug 曾让 `hit@4` 虚低 17 个百分点。
- **严格 / 宽松两套口径并列**：同一句话常同时写进多部国标，gold 只标主承载文档。
  严格只认主文档，宽松认任一承载文档，差额 `caliber_gap` 单列，不用宽松数去美化严格数。

## 指标

| 指标 | 数值 | 分母 | 怎么读 |
| --- | --- | --- | --- |
| `strict_hit@6` | **82.50%** | 40 道有答案题 | 只认主承载文档 |
| `loose_hit@6` | **87.50%** | 同上 | 任一承载文档都算 |
| `caliber_gap` | 5.00% | — | 两个口径的差，别只报高的那个 |
| `strict_mrr` / `loose_mrr` | 0.5887 / 0.6221 | 同上 | 排序质量 |
| `e2e_answer_rate` | **80.00%** | 同上 | 端到端答出来（过阈值 + 模型没拒） |
| `answerable_refused_rate` | **12.50%** | 同上 | 有答案却被拒：怎么坏的要再拆 |
| ├ `refused_after_miss_rate` | 5.00% | 同上 | 检索没排到 → 该修检索 |
| └ `refused_despite_hit_rate` | 7.50% | 同上 | 排到了还拒 → 该修 Prompt / 上下文 |
| `answered_after_miss_rate` | 7.50% | 同上 | 没检索到却答了：**最危险的一类** |
| `abstain_by_threshold` | 0.00% | 10 道无答案题 | 阈值路径拦下几道 |
| `abstain_by_llm` | 100.00% | 同上 | 模型自己拒了几道 |
| `false_answer_rate` | **0.00%** | 同上 | 真幻觉（样本 10 道，只说明这批题没漏） |

延迟 p50/p95 实测 799 / 10247 ms，**不可信**：测量时机器上另有两个 2 GB 级 Python 进程
抢 CPU；空闲时同配置是 132 / 224 ms。延迟要单独在空闲机器上量，别引用这一行。

## 三类失败模式（这才是要动手的地方）

1. **检索没排到**（`refused_after_miss_rate` 5%）：`n23` 问「大部分自动灭火系统的主要启动
   方式」，原文写「与火灾自动报警系统联动自动启动」，词面差距太大，top-20 都没进。
   这类只能靠查询改写或 rerank，调阈值没用。
2. **排到了没进 top-6**（排第 7、第 8 的 `n16`、`n20`）：同章节相邻条款互相挤占。
   切片按条文号切、而不是按 800 字定长切，能直接解决。
3. **排到了模型仍拒答**（7.5%）：上下文里其实有答案，但模型判定「没直接写明」。
   这是 Prompt 口径问题，不是检索问题——把两者混成一类，就会去调一个没坏的阈值。

## 局限（写进报告里，别藏着）

- 样本小：40 道有答案 + 10 道无答案。10 道无答案题的 95% 置信区间极宽，
  `false_answer_rate=0%` 只能说「这批题没漏」，不能说「不会幻觉」。
- 单一领域语料：全是消防规范，任意两段文本的余弦相似度天然偏高，
  纯阈值做不到零幻觉（这批无答案题 top1 最低也有 0.58），剩下靠 Prompt 兜。
- 页码有两个口径（PDF 物理页 / 页脚印刷页），带封面的标准会差一个常数。
  两个都存进 metadata 了，但历史 gold 是按压印页标的，换语料时要复核。
- 每轮扩库后必须复核 10 道无答案题：`q012` 就因加入 GB50877 而从「无答案」变成
  「有答案」，继续复用旧标注，测的就是标注陈旧度而不是模型。

## 可写成博客的三条

1. **`hit@4` 55% → 72.5% 是评测代码的 bug，不是模型变好**。第一版只把「第一个匹配的切片」
   当 gold，`chunk_overlap` 让命中落在相邻片就算失败。指标突然变难看，先查评测代码。
2. **`MIN_SCORE` 调高反而更差**。sweep 的 F1 最优点在 0.65，但完整双路评测显示：
   0.30 时误拒 0%、真幻觉 0/10；0.65 时误拒 10%，幻觉一例没少。只看阈值路径会挑到坏阈值。
3. **「必须重启服务」是个错误归因**。当晚同时刻有两个毛病，我把 55% 记到了「索引快照」头上；
   后来用探针验：外部进程写入后不重载就能检索到（第 1 名，score 1.000）。相关性不等于因果。
